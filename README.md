# Web Torrent

Личный торрент-качальщик с веб-интерфейсом. Сервер скачивает торрент у себя, а вы забираете готовые файлы обычным HTTPS-скачиванием (или смотрите видео прямо в браузере). На вашем устройстве никакого P2P-трафика нет.

- Добавление по magnet-ссылке, ссылке на `.torrent` или файлом (кнопка / drag & drop / Ctrl+V magnet прямо на страницу)
- Прогресс, скорость, пиры, оставшееся время; пауза, продолжение, отмена (с удалением недокачанного)
- **Раздача по умолчанию выключена**: сервер ничего не отдаёт другим пирам даже во время скачивания. Её можно включить переключателем на вкладке «Загрузки» и ограничить скорость ползунком
- Как только торрент скачан — раздача сразу останавливается, торрент и `.torrent`-файл удаляются, файлы переносятся в «Файлы»
- Браузер файлов: скачать файл (с докачкой), скачать папку zip-архивом, удалить
- Встроенный плеер для видео/аудио с перемоткой; временные прямые ссылки для VLC / ТВ / wget
- Индикатор свободного места на диске
- Один пользователь, пароль хранится хэшем (scrypt), защита от перебора, HttpOnly-сессии, CSRF-защита, HTTPS через Let's Encrypt

## Быстрый старт на сервере (Ubuntu 22.04/24.04 или Debian 12)

```bash
ssh root@ВАШ_IP
apt-get update && apt-get install -y git
git clone https://github.com/afomin/web-torrent.git
cd web-torrent
./install.sh
```

Скрипт установит Docker, спросит логин и пароль, откроет порты и запустит всё. Адрес будет вида
`https://203-0-113-7.sslip.io` — это бесплатный домен, который указывает на ваш IP; он нужен, чтобы получить настоящий HTTPS-сертификат (по голому IP Let's Encrypt сертификат не выдаёт).

Если у провайдера есть облачный фаервол (Oracle, Hetzner, AWS…), откройте в его панели: **TCP 80, TCP 443, TCP+UDP 51413**.

### Управление

```bash
docker compose logs -f app      # логи
docker compose restart app      # перезапуск
git pull && docker compose up -d --build   # обновление
docker compose down             # остановить
```

Файлы лежат в `./downloads`, состояние — в `./data`.

Сменить пароль: `docker compose run --rm --no-deps -e PASSWORD_TO_HASH='новый-пароль' app node scripts/hash-password.js`, вставить результат в `.env` в `AUTH_PASSWORD_HASH='...'` (в одинарных кавычках) и сделать `docker compose up -d`.

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DOMAIN` | — | Домен для HTTPS, например `1-2-3-4.sslip.io` |
| `AUTH_USERNAME` | `admin` | Логин |
| `AUTH_PASSWORD_HASH` | — | Хэш пароля (`npm run hash-password`) |
| `AUTH_PASSWORD` | — | Альтернатива: пароль открытым текстом |
| `SESSION_DAYS` | `30` | Сколько дней помнить вход |
| `TORRENT_PORT` | `51413` | Порт BitTorrent (TCP+UDP) |
| `DOWNLOAD_LIMIT_KBPS` | `-1` | Ограничение скачивания, КБ/с |
| `MAX_CONNS` | `100` | Максимум соединений на торрент |

## Про видео в браузере

Видео отдаётся как есть, без перекодирования (дешёвому серверу это не по силам). MP4 (H.264/AAC) и WebM играют везде; MKV в Chrome/Edge обычно играет, если внутри H.264 + AAC. HEVC/x265, AC3/DTS-звук браузеры часто не поддерживают — тогда нажмите «Ссылка для VLC» и откройте ссылку в VLC (Медиа → Открыть URL) или на телевизоре.

## Локальная разработка

```bash
npm install
AUTH_PASSWORD=devpassword123 npm start   # http://127.0.0.1:3000
npm test                                 # e2e-тесты с настоящей торрент-загрузкой через локальный трекер
```

## Безопасность

- Без входа доступна только страница логина; все API и файлы требуют сессию.
- Cookie `HttpOnly`, `SameSite=Strict`, `Secure`; все изменяющие запросы требуют заголовок `X-Requested-With`.
- 5 неверных попыток входа с одного IP → блокировка на 15 минут.
- Доступ к файлам только внутри папки загрузок (защита от `../` и симлинков).
- Прямые ссылки подписаны HMAC и истекают (6 ч / 24 ч / 7 дней). Чтобы отозвать все ссылки разом, удалите `data/secret.key` и перезапустите приложение.
- Приложение слушает только `127.0.0.1`; снаружи доступен лишь Caddy на 80/443.
